# כיוונון ומטמון בוט ניהול האתר

גרסה 2.71.0 מוסיפה כיוונון למוצר בוט ניהול האתר ומטמון מפורש ב־Gemini. תוסף WordPress נשאר בגרסה 1.11.0; שינוי זה מתבצע באפליקציה. הגישה להגדרות ולבנייה מחדש מוגבלת למנהלי מערכת.

## הגדרות

ב־**הגדרות ← בוט ניהול אתר**:

| הגדרה | ברירת מחדל | טווח |
| --- | --- | --- |
| אישיות ותפקיד, סגנון, כללי עבודה, הנחיות נוספות | התנהגות הסוכן הקיימת | עד 4,000 תווים בכל שדה |
| הודעות קודמות בהקשר | 40 | 0–80; אפס משבית את היסטוריית השיחה |
| חלון היסטוריה | 168 שעות | 1–2,160 שעות, בתוך תקופת השמירה |
| היסטוריה ותוצאות פעולות בהקשר | 24,000 תווים | 0–48,000 |
| שמירת תמלילים | 7 ימים | 1–90 ימים |
| סבבי מודל להודעה | 6 | 2–10 |
| חלון התחלת קריאות כלים | 240 שניות | 30–240; קריאה שהתחילה ותשובת סיכום עשויות להסתיים מאוחר יותר |
| תשובות כלי קריאה רגילים | 6,000 תווים | 1,000–12,000; לכלים מובנים כגון ACF גבולות נפרדים |
| מטמון מפורש | פעיל ב־Gemini | הפעלה או כיבוי |
| תוקף מטמון | 60 דקות | 15–1,440 דקות |

שדה טקסט או מספר שנמחק חוזר לברירת המחדל, גם בתהליכי תור ממושכים. ערך אפס בהגדרות ההיסטוריה נשמר כאפס. ההגדרות נכנסות לתוקף לאחר שמירה. התאמת סגנון אינה מבטלת כללי אישור, הרשאות, קריאת מצב עדכני, פרטיות או מגבלות הפעולות.

## מה נשמר ומה נשלח

`GeminiContextCache` יוצר `cachedContents` עם הוראות המערכת הקבועות וקטלוג הכלים הזמין. קריאות `generateContent` משתמשות ב־`cachedContent` ומוותרות על שליחה חוזרת של `systemInstruction` ו־`tools`. הזמן, הדומיין, שם הדובר, ההודעה החדשה, ההיסטוריה ותוצאות הכלים נשארים מחוץ לתוכן שנשמר אצל הספק.

המפתח כולל לקוח ואתר, כתובת ספק, מודל, טביעת מפתח API, ההנחיות, סכמות הכלים, תוקף וגרסת איפוס. שינוי מהותי מייצר משאב חדש. מספרים מורשים באותו אתר יכולים להשתמש באותו קטלוג קבוע; היסטוריית השיחה נשארת נפרדת לכל מנוי. המטמון המקומי שומר מזהה ספק, תוקף וטביעות התאמה, ללא תוכן השיחה או מפתח API גלוי.

ההפניות נשמרות במנגנון המטמון הקיים של Laravel. בייצור נדרש backend מתמשך כגון database, Redis או file, המשותף לתהליכי העבודה הרלוונטיים. מחיקת המטמון המקומי גורמת ליצירה מחדש בשימוש הבא; משאבים ישנים אצל Google פגים לפי תוקפם.

## חידוש ותקלות

Google מחייב תאריך תפוגה. המטמון מתחדש לקראת פקיעה בזמן שימוש באמצעות PATCH של TTL, ונבנה מחדש אם כבר פג. אין משימה שמאריכה לנצח מטמון של אתר שאינו פעיל. נעילה קצרה מונעת יצירות מקבילות; תהליך שלא השיג אותה ממשיך ללא מטמון במקום להמתין.

יצירה או חידוש מוגבלים בזמן. מודל שאינו תומך במטמון, קלט קצר מדי או תקלה מפעילים השהיית ניסיון חוזר ומעבר לבקשה מלאה. דחייה מזוהה של הפניית מטמון מאפשרת ניסיון אחד של אותה בקשת מודל ללא מטמון. ההיסטוריה שנצברה נשמרת ולא מופעל שוב כלי שכבר טופל. שגיאות ספק אחרות אינן מקבלות ניסיון חוזר אוטומטי במסלול הזה.

**בנייה מחדש בשימוש הבא** משנה את דור המטמון המקומי. הפעולה אינה שולחת בקשת רשת ממסך הניהול, אינה שומרת עריכות שטרם נשמרו ואינה מוחקת מיד עותקים אצל Google. מצב המטמון במסך מתייחס לתצפית האחרונה עבור ההגדרות השמורות; הוא אינו טוען שכבר נוצר מטמון לכל אתר.

## עלויות וגבולות אימות

Google עשוי לגבות גם על אחסון לפי נפח ומשך זמן. הארכת TTL משפרת זמינות בין הודעות ועשויה להגדיל דמי אחסון. לאחר שינוי הנחיות או איפוס, המשאב הישן והחדש יכולים להתקיים עד לפקיעת הישן.

`cachedContentTokenCount` הוא חלק מתוך `promptTokenCount`, ולא תוספת אליו. הטוקנים נשמרים במונה `cached_input_tokens` בטבלאות השימוש הכללית והמשויכת ללקוח. במסך **הגדרות ← סוכן AI** מוצגים הכמות ושיעורה מתוך הקלט. נתונים היסטוריים אינם משוחזרים; מדידה זו מתחילה לאחר העדכון. אומדן הדולרים הקיים עדיין משתמש במחיר הקלט הרגיל ואינו כולל הנחות או אחסון מטמון; הוא אינו חשבונית ואינו תקרת עלות.

הבדיקות משתמשות בלקוחות ובמסלול השיחה האמיתיים, עם הדמיית HTTP. הן מכסות שימוש חוזר, זמן והקשר עדכניים, הפרדה בין לקוחות ואתרים, שינוי הגדרות והרשאות, פקיעה וחידוש, תקלות, איפוס במקביל לבקשה, אישור ושינוי מצב לפני אישור. לא בוצעה קריאת API חיה בחשבון הלקוח. תמיכה, דרישת מינימום ותמחור של `gemini-3.1-flash-lite` נקבעים לפי חשבון Google וה־API; לא הוטמעו מספרי סף או מחירים שלא אומתו.

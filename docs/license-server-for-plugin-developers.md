# שרת הרישיונות של Multi Digital — למפתח התוסף

המסמך הזה אומר **לאן לפנות ומה יחזור**. הוא מאשר את המפרט שסוכם (`license-api.md`)
ומוסיף את מה שהמימוש בפועל עושה — ההתנהגויות שכדאי להכיר כדי לא לבנות סביבן
עקיפות מיותרות.

הצד השני של החוזה הזה הוא חנויות של לקוחות שאף אחד מאיתנו לא יכול לפרוס אליהן
קוד. לכן: **הוספת שדות בטוחה, שינוי צורה — לא.**

---

## כתובת הבסיס

```
https://app.multidigital.co.il/api/license/v1
```

בתוסף, כדי לאפשר החלפה לסביבת בדיקות בלי לגעת בקוד:

```php
define( 'WC_STORE_ENHANCER_LICENSE_API', 'https://app.multidigital.co.il/api/license/v1' );
```

| | |
|---|---|
| **פרוטוקול** | HTTPS בלבד. |
| **שיטה** | `POST`, גוף `application/x-www-form-urlencoded` — כלומר `wp_remote_post` כברירת מחדל. (גם JSON מתקבל.) |
| **אימות** | אין. מפתח הרישיון הוא האישור — אין טוקנים ואין כותרות. |
| **הגבלת קצב** | 30 בקשות לדקה לכל IP. חריגה מחזירה `429`. |

### מה נשלח בכל בקשה

| שדה | חובה | הערות |
|---|---|---|
| `key` | ✔ | המפתח כפי שהלקוח הדביק. |
| `site` | ✔ | `home_url()`. |
| `version` | | גרסת התוסף המותקנת. |

**אין צורך לנקות את `key` ואת `site`.** רווחים בקצוות, אותיות קטנות ומפתח בלי
מקפים — כולם מתקבלים ומנורמלים אצלנו.

## נקודות הקצה

### `POST /activate` · `POST /check` · `POST /deactivate`

`activate` ו-`check` מחזירות את אותו אובייקט:

```json
{
  "status": "valid",
  "expires": "2027-08-16",
  "sites_limit": 3,
  "sites_used": 1,
  "message": ""
}
```

| שדה | הערות |
|---|---|
| `status` | `valid` · `expired` · `limit` · `invalid`. כל ערך אחר — התייחסו כאל `invalid`. |
| `expires` | `YYYY-MM-DD`. **מחרוזת ריקה = ללא תפוגה.** |
| `sites_limit` | **0 = ללא הגבלה.** |
| `sites_used` | כמה אתרים רשומים כרגע. |
| `message` | עברית, **מיועד להצגה ללקוח כמו שהוא**. ריק כשהכל תקין. |

`deactivate` מחזירה תמיד `{"status":"inactive","message":""}` — גם למפתח שאינו
מוכר. אין מצב שבו היא נכשלת.

> ### ⚠️ הכלל שקובע את כל השאר
>
> **כל תשובה עסקית חוזרת עם `200`** — כולל `expired`, `limit` ו-`invalid`.
>
> `5xx`, `429` או ניתוק הם **תקלת תקשורת**, ובמקרה כזה על התוסף **לשמור על המצב
> הקודם** ולא לבטל את הרישיון. זו לא הנחיה תיאורטית: דקה של תחזוקה אצלנו הייתה
> מבטלת רישיונות בכל החנויות בבת אחת.

### `POST /update`

הצד היחיד שמחזיר קוד שגיאה: **`403`** כשהרישיון אינו מכסה את האתר. הגוף מכיל
`{"status":"...","message":"..."}` — התוסף פשוט לא יציג עדכון.

בהצלחה:

```json
{
  "version": "1.23.0",
  "download_url": "https://app.multidigital.co.il/api/license/v1/download?k=…&site=…&exp=…&sig=…",
  "homepage": "https://multidigital.co.il/wc-store-enhancer",
  "requires": "6.4",
  "requires_php": "8.0",
  "tested": "9.9",
  "changelog": "<ul><li>תיקון בחירת וריאציה</li></ul>",
  "last_updated": "2026-08-16 10:00:00"
}
```

**מקרה אחד שכדאי לטפל בו:** תוסף שעדיין לא הוגדרה לו גרסה מופצת מחזיר `200` עם
`{"status":"valid","message":""}` **בלי** שדה `version`. זה לא כישלון רישיון — זה
"אין עדכון". אל תציגו שגיאה.

### `GET {download_url}`

וורדפרס פונה לכתובת הזו **בעצמו**, בלי כותרות מהתוסף. הכל נמצא בכתובת:

- **המפתח לא מופיע בה** — מה שנשלח הוא גיבוב שלו.
- **חתומה ותקפה לשעה.**
- **קשורה לאתר אחד** — קישור שנתפס לא יעבוד מאתר אחר.

הקישור נבדק שוב בזמן ההורדה: רישיון שבוטל בין הרגע שבו נוצר הקישור לרגע ההורדה
ייחסם, גם בתוך שעת התוקף. כל סירוב מחזיר `403` באותה צורה.

## מה המימוש שלנו עושה — ולמה זה חוסך לכם עבודה

**הפעלה חוזרת מאותו אתר אינה תופסת מקום נוסף.** הבדיקה "האם האתר כבר רשום"
קודמת לבדיקת המכסה. אין צורך לקרוא ל-`deactivate` לפני `activate` מחדש.

**כתובת האתר מנורמלת אצלנו:** סכימה, `www.` ולוכסן בסוף מוסרים, והשוואה היא
case-insensitive. כלומר:

```
http://shop.co.il  ==  https://www.shop.co.il/  ==  https://shop.co.il
```

מעבר ל-HTTPS, הוספת `www` או שחזור גיבוי — כולם אותו אתר, ולא ייגמר ללקוח
המקום במכסה בגללם. **שלחו את `home_url()` כמו שהוא**; אל תנרמלו בצד שלכם.

**`check` לעולם אינו רושם אתר חדש.** אתר שאינו רשום מקבל `invalid` עם הודעה
שמסבירה מה לעשות. רק `activate` תופס מקום.

**`check` מעדכן אצלנו `last_seen` ו-`version`.** שלחו `version` גם בבדיקה
היומית — כך אנחנו יודעים מי מריץ איזו גרסה, וזה מה שמאפשר לנו לומר ללקוח מה
בדיוק מותקן אצלו כשהוא פונה לתמיכה.

**פקיעה עוצרת עדכונים בלבד.** התוסף חייב להמשיך לעבוד באתר במלוא התפקוד. זו
החלטה עסקית מפורשת אצלנו, וההודעה שמוחזרת ב-`expired` כבר אומרת ללקוח בדיוק את
זה — הציגו אותה כמו שהיא.

## פורמט המפתח

```
XXXX-XXXX-XXXX-XXXX
```

מהאלפבית `A-Z` ו-`2-9` — **בלי התווים O, 0, I ו-1**, שמתבלבלים בהכתבה טלפונית
ובצילום מסך.

בצד שלכם: אל תדחו מפתח על סמך פורמט. שלחו אותו כמו שהוא ותנו לתשובה להכריע — כך
תיקון בעתיד לא מחייב עדכון תוסף בכל החנויות.

**המפתח אינו נשמר אצלנו כטקסט**, רק גיבוב שלו. משמעות מעשית אחת: אנחנו לא יכולים
לשלוח ללקוח את המפתח שלו שוב. מפתח שאבד — מונפק מחדש, והישן מפסיק לעבוד מיד.
כדאי שהודעת השגיאה על `invalid` תרמוז ללקוח לבדוק את המייל שקיבל.

## איך בודקים שהחיבור עובד

1. תבקשו מאיתנו מפתח בדיקה. הדביקו אותו באתר תחת **הגדרות ← רישיון** → אמור להופיע "פעיל".
2. נגדיר בצד שלנו גרסה גבוהה מהמותקנת. בעמוד התוספים בוורדפרס אמור להופיע עדכון — מיד אחרי "בדוק עדכונים עכשיו", או תוך 6 שעות.
3. "עדכן" → ההתקנה אמורה להצליח.
4. נעביר את התוקף לעבר. בבדיקה הבאה: "פג תוקף", העדכונים נעצרים, **והתוסף ממשיך לעבוד רגיל**.
5. הפעילו על אתר שני מעבר למכסה → `limit`, והתוסף אמור להציג את ההודעה שחזרה.

## איך גרסה מגיעה ללקוחות

**אין העלאת קבצים ידנית.** המערכת מסנכרנת את המאגר שלכם ב-GitHub אחת לשעה.

1. פרסמו **Release** במאגר עם תג `v1.2.3` (או `1.2.3`).
2. **צרפו ל-Release קובץ ZIP בנוי** — בדרך כלל מ-GitHub Action. זו הדרך הנכונה, ובלעדיה הגרסה לא תיקלט.
3. גוף ה-Release הופך ל-changelog שהלקוח רואה ב"הצג פרטים" בוורדפרס. שורה לפריט.

**למה נדרש קובץ מצורף ולא ארכיון הקוד של GitHub:** הארכיון האוטומטי עוטף הכל
בתיקייה בשם `repo-1.2.3`. וורדפרס היה מתקין את התוסף לתיקייה שמשתנה בכל גרסה
ומאבד אותו — העדכון הבא היה מתקין עותק שני לצד הראשון, שניהם פעילים. בנוסף
המאגר אינו התוסף: יש בו בדיקות, קובצי בנייה ו-CI שאין להם מה לעשות בחנות של
לקוח.

(אם המאגר שלכם *הוא* בדיוק מה שצריך להיארז, אפשר להפעיל אצלנו אריזה מהקוד —
תגידו ונדליק. ברירת המחדל היא לדרוש קובץ בנוי.)

**טיוטות ו-pre-releases נקלטות? לא.** הן פורסמו במפורש כ"לא לכולם".

**גרסה שנקלטה אינה מופצת מיד.** היא מחכה להחלטה בצד שלנו — שליחת בילד לכל
החנויות בבת אחת היא לא דבר שקורה מעצמו. אם דחוף, תגידו ונפיץ.

**מאגר פרטי:** נצטרך ממכם Fine-grained token עם הרשאת **Contents: Read בלבד**
על אותו מאגר.
